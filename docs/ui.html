Kept UI: screens, shells and rules

This is the UI for Kept v0 as built in the kept-ui lab (github.com/w-ade/kept-ui). Every screen exists and runs. Build the real product to match it. The code in src/kept is the source of truth; this doc explains what it does and why.

It pairs with the Kept v0 plan (kept-v0.html). The plan says what v0 is; this says what it looks like and how it behaves.

  → /m/:token Board (public, no sign-in)

In the lab every route is prefixed with #/kept, so the Kept screens never collide with the lab's own pages. Create collection and share/publish are dialogs, not pages.

Design language

Modeled on the base-ui.com homepage, not its docs pages: one quiet grid, labels in the left gutter, hairline-ruled lists, text links instead of buttons. Strip things down before adding anything.

Grid

  • 8 columns. Gap 2.5rem, 3rem from 48rem. Max width 1480px, centered.
  • Page padding 1.5rem; from 48rem, 2rem top and bottom and 3rem on the sides.
  • Sections use display: contents, so their children sit directly on the page grid. The row gap is the only vertical rhythm.
  • Placement below is in grid lines, 1 to 9 (so 3–9 means the last six columns).
  • Label column: full width, then 1–3 from 48rem.
  • Body column: full width, then 3–9 from 48rem, then 3–7 from 80rem.
  • Wide column (tile grids): full width, then 3–9 from 64rem.
  • Hero (page titles): full width, then 1–5 from 80rem.
  • Breakpoints: 48rem, 64rem, 80rem. Mobile first. Below 48rem everything is one column.

Type

  • Geist Sans for everything, Geist Mono where code shows. Weight 400 throughout; only the KEPT wordmark is bold.
  • Small text: 15px on a 22px line. Nav, labels, captions, meta.
  • Body text: 18px on a 25px line. Paragraphs, list rows, inputs, section labels.
  • Display: 34px on a 34px line, then 42px on a 44px line from 48rem. Page titles only.
  • Sentence case everywhere. Page titles don't end with a period, except the landing headline, which is a sentence.

Color

  • Tokens come from the Base UI docs (src/docs.css). Light and dark follow the system setting.
  • Page background: gray-s1. Text and rules: gray-t2. Muted text: gray-t1. Placeholder text: gray-p1.
  • Placeholder images: gray-c1, a super light gray square.
  • Errors and destructive actions (Unpublish): poppy-t1. No other accent color.

Rules, lists and separators

  • Lists are ruled rows: a 1px gray-t2 rule above the list and below every row, 12px vertical padding, two equal columns.
  • Between sections: a separator, a 32px hairline in gray-s2. It's meant to be barely there.
  • Form fields are ruled rows too. On phones the label sits above the input; from 48rem, label and input sit side by side.

Links and buttons

  • Links are underlined (1px, 4px offset). Hover removes the underline. Press inverts the colors.
  • The current page is gray with no underline.
  • Arrow links ("Open the library ›") are the main call to action. On hover the caret slides 4px right and a shaft appears. Back links flip the arrow.
  • Buttons are Base UI Buttons styled as text links. Disabled reads as gray-p1 with no underline. There are no filled or outlined buttons.
  • Anything that navigates is a plain link (a), never a Button.

Images

Until real files exist, every image is a light gray square: square tiles in grids, a small square in list rows, a large square on the reference page and in the board lightbox. Collection tiles use a 2×2 mosaic of squares, one filled square per reference (up to four), with outlined empty squares when there are fewer.

Focus and motion

  • Focus: 2px outline in the current text color, 2px offset. A focused field thickens the rule under it instead of drawing a box.
  • Motion is CSS only, through Base UI's data-starting-style and data-ending-style: fades and small slides, 100–300ms, ease-out. No Motion package in v0.
  • Honor prefers-reduced-motion: the arrow slide, pin drop, new-collection fade and dialog slide turn off.

Shells

Four shells, all on the same grid. No dashboard layout.

  • Marketing (landing): KEPT wordmark top left, a stacked nav of text links (Landing, Library, Map), "Early development" on the right from 64rem. Footer: "© Kept".
  • Auth (sign in, two-factor, request an invite): the same header with only a Landing link.
  • App (library, collection, reference): nav is Library, Map, Sign out. The signed-in username sits on the right from 64rem. Gated: no session sends you to /login; a session without two-factor sends you to /login/mfa.
  • Board (/m/:token): no header, no nav, no sign-in. Its own footer: "Made with KEPT, a library you can actually operate."

Screens

Landing (/)

  • Headline: "A library you can actually operate." Then an arrow link: "Open the library".
  • Intro, in the body column: "A structured system for collecting, organizing, contextualizing, and retrieving visual references."
  • Access: "Kept is invite-only while it's in early development. Every account is let in by hand." Two rows: Members → Sign in, Everyone else → Request an invite.
  • Fundamental actions, seven rows: Capture (Create a record.), Index (Give it structure.), Annotate (Add meaning.), Organize (Put it into collections / relationships.), Query (Search and filter it.), Retrieve (Actually find it again.), Connect (Relate one reference to another.).
  • The project, three rows: DF.4.2 (Visual working surface), RG.001 (Reference system), Status (Active).

Sign in (/login)

  • Kept is invite-only, so there is no sign-up. The intro says so and links to Request an invite.
  • Username and password, as ruled field rows with no placeholders. Username: 2–32 letters, numbers, dots, dashes or underscores.
  • Continue is an arrow-styled Button. While sending it reads "Signing in…" and is disabled.
  • Errors under the field, in poppy: "Enter your username." / "Enter your password." / "Usernames are 2–32 letters, numbers, dots, dashes or underscores." / "Username or password is incorrect." The last one sits on the password field and clears as soon as it's edited.
  • Success goes to /login/mfa in the real app. The lab skips straight to /library.

Two-factor (/login/mfa) and Request an invite (/request)

Placeholders in the lab. Two-factor has its own route, so a refresh mid-challenge keeps you on it.

Library (/library)

  • Title "Library", then a count: "1 collection, 160 references."
  • Label column: "Collections" and "New collection +", which opens the create dialog.
  • Wide column: search between two rules ("Search collections"), then the tile grid: 2 across, 4 from 48rem, 6 from 64rem.
  • Each tile: the 2×2 mosaic, the name, and the reference count in muted text. The name underlines on hover.
  • No match: "No collections match “…”."
  • All references: every reference from every collection in one section below Collections, with the same Grid / List switch and search as a collection page. Each item's second line is its collection's name. Opening one goes to its reference page inside its collection.
  • New collection dialog: one Name field (required, up to 80 characters, "Give it a name."), then Cancel and Create ›. The new collection goes first in the grid with a short fade.

Collection (/library/:collectionId)

  • "‹ Library" back link over the title. Then "160 references. Updated Sep 18, 2026." and the share line: "Not shared. Share as a board ›" or "Shared as a board. Manage ›".
  • Description: a ruled text box that grows with its text ("What is this collection for?"). It also shows under the title on the collection's board, line breaks kept.
  • Add images +: opens the upload dialog (a Base UI Dialog). "Choose images" opens the phone's photo picker (library, camera or files), several at a time; on desktop, images can also be dropped on the dialog. Each file gets a row: Waiting, Adding…, Added, or "Couldn’t read this file" in poppy, with a running "Adding 3 of 12…". Done is disabled until it finishes. Images are resized on the device (1600px full, 480px thumbnail, metadata removed); the file name becomes the title and the source reads Uploaded. New images go first.
  • Label column: "References" and a Grid / List switch. The current option reads like the current page: gray, no underline. The choice is remembered.
  • Search ("Search titles, tags, notes") also matches source site, file name and pin captions.
  • Grid: square, title, source site ("fontsinuse.com" or "Uploaded", with an ellipsis if long). A small black badge counts pins.
  • List: small square, title, source site, and file type from 48rem.
  • Empty collection: "Nothing kept here yet." No match: "No references match “…”."

Reference (/library/:collectionId/:referenceId)

Selecting an image selects the Reference, with its file as the focused Asset. Meaning first, file facts second.

  • Breadcrumb "Library / moode-matcha" over the title. Then "1 of 160" with ‹ Previous and Next ›. ← and → step through the collection and Esc goes back to it, but never while typing. Previous and Next go gray at the ends.
  • Image: the large square. Tap to drop a numbered pin where you tapped; keyboard activation drops it in the center. The new pin's caption field takes focus.
  • Notes: a ruled text box that grows with its text ("What's worth remembering about this one?").
  • Tags: outlined pill chips, each with × to remove. "Add a tag" takes Enter, a comma or blur. Duplicates are ignored regardless of case.
  • Annotations: numbered ruled rows with an editable caption and Remove. Hovering or focusing a row enlarges its pin on the image. Empty: "No annotations yet. Tap the image to drop a pin."
  • Collections: the collections it belongs to, as links.
  • File: Name, Type, Pixel size, Size, Added, Source (the capture URL, or "Uploaded").
  • Show blank fields with an empty state instead of hiding them. Don't invent data: no year, no OCR, no guessed metadata.

Share dialog (from a collection)

  • "Anyone with the link can view “…” as a read-only board. It isn't listed or searchable anywhere."
  • Not published: Cancel and Publish ›.
  • Published: the link with Copy (reads "Copied" after), the publish date, New link (the old link stops working at once, and the dialog says so), Unpublish in poppy, then Open board › and Done.
  • Copy falls back to select-and-copy where the clipboard API isn't available (plain http).

Board (/m/:token)

  • Collection name, then "Kept by wade · 160 references · Published Sep 18, 2026".
  • Full-bleed grid, tighter than the site grid so it reads as one surface: 2 across, 3 from 48rem, 4 from 64rem, 5 from 80rem. Each item: square and title.
  • Tapping an image opens a full-screen lightbox: "1 of 160" and Close, the image with its pins, then title, source, notes and pin captions, and ‹ Previous / Next ›. ← and → step, Esc closes. The image is as large as fits, capped at 70% of the screen height so the caption starts in view.
  • Bad, rotated or unpublished link: "This board isn't available" and "The link may be wrong, or its owner has unpublished it or made a new link."
  • Empty board: "This board is empty."

System map (/map)

  • Flow: the plan's tree (You → Library → References, Notes and tags, Annotations, Search, Share → Board → Anyone with the link), stepping in by depth.
  • Then ruled term | detail sections: 1 · Capabilities, 2 · Domain model (with the table list), 3 · Application, 4 · Data, 5 · Infrastructure, How it connects, and Later, not v0.

Kept on iOS (/ios)

  • Linked from the last section of the system map, "Mobile plans (upcoming)". Same layout as the map, with a "‹ System map" back link.

Base UI parts

Every interactive control goes through Base UI; layout is plain CSS.

  • Button: Continue, Sign out, Create, Publish, Copy, New link, Unpublish, Remove, tag ×, lightbox Previous / Next.
  • Form and Field: sign in and new collection. Field.Error per validity state, plus a controlled Field.Error for server errors.
  • Input: searches, tag entry, pin captions, the board link.
  • Dialog: new collection and share (bottom sheet on phones, centered from 48rem, 1px gray-t2 border, 8% backdrop), and the board lightbox (full screen).
  • ToggleGroup and Toggle: the Grid / List switch.
  • Gotcha: Field owns its control's id, so find inputs by a data attribute, not by id.
  • Gotcha: Field.Error with match="customError" doesn't show errors passed through the Form errors prop. Render the server error yourself with match set to true, and clear it when the field changes.

Data the UI expects

  • Collection: id, name, description, reference count, updated date.
  • Reference (meaning): title, notes, tags, pins (normalized x/y plus caption), added date, capture URL or null for uploaded.
  • Asset (file facts): file name, type, width, height, bytes. v0 has one asset per reference; show a count later if there are more.
  • Share: token, owner, published date. Publish, rotate and unpublish; the board is read by token only.
  • src/kept/repository.ts is a mock with this exact interface. Swap in Supabase behind the same functions.

Lab only, not decisions

  • Sign-in is mocked: one account, wade / 1234. Two-factor is skipped.
  • Notes, tags, pins and collection descriptions are saved in the browser, so they survive reloads on that device only. New collections are saved too. Shares also persist in the browser, so a board link only opens on the device that published it (the built-in moode-matcha board opens anywhere).
  • Uploads are saved in the browser (IndexedDB) and new collections in localStorage, so they stay on the device they were made on.
  • Not built yet: box annotations (pins only), two-factor, request an invite, link previews for shared boards.
